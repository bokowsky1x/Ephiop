# Ephiop

[原始中文文档](README.zh-CN.md)

Веб-панель управления аккаунтами Telegram на русском языке.

## Возможности этой версии

- Русский интерфейс, уведомления и сообщения об ошибках.
- Редактирование имени, фамилии, описания, @username и фотографии Telegram через кнопку с карандашом в списке аккаунтов; отдельное название аккаунта в панели.
- Изображения JPEG, PNG и WebP в автоответах и задачах по расписанию.
- Сообщения с изображением без текста или с подписью до 1024 символов.
- Замена, просмотр и удаление вложения при редактировании.
- Сохранение изображений в отложенных ответах, повторная отправка при ошибке.
- Импорт аккаунтов Telegram Desktop из ZIP-архива `tdata`.
- Распознавание русского времени, например `2 часа 30 минут` или `1 ч 20 мин`.

## Запуск

Нужен Python 3.10 или новее.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.venv\Scripts\python migrate.py
.venv\Scripts\python main.py
```

На Linux используйте `.venv/bin/python` и `cp .env.example .env`.
В `.env` задайте собственный `SECRET_KEY`. Панель открывается по адресу
http://127.0.0.1:5000. Новые столбцы для вложений и tdata добавляются автоматически
при запуске, существующие записи сохраняются.

## Профиль аккаунта

На странице профиля поле «О себе» загружается из полного профиля текущего
аккаунта в Telegram. Кнопка «Обновить из Telegram» повторно запрашивает данные,
в том числе после изменений в другом клиенте. Описание можно заменить через
«Сохранить описание» или очистить кнопкой «Удалить описание» с подтверждением.
Имя и фамилия сохраняются отдельно и не очищают описание. Если Telegram
недоступен, редактор описания не показывается как пустой профиль.

## Вступление в чат

В разделах «Аккаунты» и «Задачи по расписанию» доступна кнопка «Вступить в чат».
Укажите публичную ссылку `t.me/имя`, `@username` или приглашение `t.me/+код`,
выберите один аккаунт или все. Запросы выполняются последовательно; результат
показывается для каждого аккаунта. Отключённые аккаунты не включаются автоматически.
Оставляйте страницу открытой до завершения. При одобрении администратором статус
«Заявка отправлена» ещё не означает членство. После успешного вступления чат
появляется в сохранённых получателях для задач. Право отправлять сообщения
зависит от настроек чата; вступление само по себе не даёт права публикации в канале.

## Изображения

В разделе «Автоответы» или «Задачи по расписанию» выберите файл в поле
«Изображение». Текст становится подписью и может быть пустым. Допустимы JPEG,
PNG и WebP до 10 МБ и 20 миллионов пикселей; перед сохранением файл преобразуется
в JPEG. В редакторе можно заменить вложение или отметить «Удалить изображение».

Файлы находятся в `instance/uploads`. Сохраняйте эту папку вместе с базой
`instance/tgbot.db`. Старые изображения не удаляются автоматически, поскольку
они могут использоваться уже сформированными отложенными ответами.
Docker сохраняет базу и изображения в существующем томе `./data`.

## Задачи по расписанию

Для задачи можно выбрать один аккаунт, несколько участников или все текущие
активные авторизованные аккаунты. Состав сохраняется при создании или редактировании;
новые аккаунты подключаются после повторного сохранения режима «Все».
Участники публикуют по очереди в порядке ID аккаунтов. Каждый запуск отправляет
одно сообщение от следующего доступного участника, а интервал задаёт паузу между
сообщениями всей задачи. Например, при интервале 60 минут: A отправляет первый
скриншот, через час B отправляет второй, затем A отправляет третий.

Все участники используют один пул и одну историю без повторов. Позиция очереди
аккаунтов хранится в базе. Отключённые, неавторизованные, неподключённые и находящиеся
вне рабочего времени аккаунты пропускаются без расходования скриншота. Если доступных
участников нет, задача ожидает. Рабочие часы аккаунта используют время сервера
и действуют также на задачи и отложенные автоответы. Разовая задача отправляет
одно сообщение от одного доступного участника.

При удалении аккаунта его личные задачи, правила и ожидающие ответы удаляются.
Общие задачи сохраняют пул и продолжают работу с остальными участниками. Журнал
остаётся, а отправитель использованного скриншота записан в истории по ID.

При изменении интервала планировщик применяет новое значение сразу. У новых
интервальных задач включена «Первая отправка сразу»: затем отправки идут через
заданный интервал. Случайная задержка, если задана, добавляется перед отправкой.
Для единственного сообщения выберите «Разовая отправка»: оставьте дату пустой
для отправки сейчас или укажите будущее время UTC. Нужен подключённый аккаунт;
если он недоступен, отправка ожидает подключения. Cron также использует UTC.

Вместо одного повторяемого изображения можно загрузить «Пул скриншотов без
повторов». Пул отдельный для каждой задачи: за запуск отправляется одна картинка
в порядке добавления. До 50 файлов за загрузку, общий запрос до 64 МБ. Одинаковые
нормализованные изображения внутри задачи пропускаются, включая уже использованные.
История хранится в базе и сохраняется после перезапуска. После окончания пула
задача завершается; добавьте новые картинки в редакторе и включите её снова.
Разовая задача отправляет только одну картинку даже при наличии пула.

Поле «Или папка со скриншотами» загружает JPEG, PNG и WebP из выбранной папки,
включая подпапки. Файлы идут по имени с естественным порядком чисел: `2` перед
`10`. Другие файлы пропускаются. Для выбранных отдельных файлов сохраняется
порядок загрузки. Ограничения количества и размера общие для обоих полей.

### Разные подписи через OpenAI

На сервере добавьте переменную `OPENAI_API_KEY` с вашим ключом OpenAI API.
Модель задаётся через `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`). На Render
это переменные раздела Environment вашего сервиса; после изменения перезапустите
сервис. Для локального запуска укажите их в `.env`. Ключ не вводится в задаче
и не должен попадать в Git. После обновления установите зависимости из
`requirements.txt`; новые поля базы добавляются при запуске автоматически.

Создайте задачу, загрузите пул, задайте интервал `60` или `120` минут. В поле
«Текст сообщения / основа для AI» напишите смысл будущих подписей. Выберите
«AI: разные формулировки», язык и максимум символов. Есть русский,
английский, амхарский, оромо, тигринья и другие языки, а также произвольный язык.
Кнопка «Пример подписи» генерирует пример по тексту, без отправки в Telegram.

В отдельном поле «Инструкции для AI» задайте стиль, лексику, оформление валюты
и правила упоминания суммы (до 4000 символов). Это настройки поведения модели,
а основа текста и скриншот остаются источниками фактов. Поле необязательное:
существующие задачи без инструкций работают как раньше. Инструкции используются
и при отправке, и в примере подписи; пример по-прежнему не читает скриншот.
Изменение инструкций сбрасывает подготовленные подписи только у ожидающих
скриншотов, сохраняя историю отправок. Правила не разрешают выдумывать суммы,
валюту и другие факты. Просьба «упоминать сумму изредка» не гарантирует точную
частоту; естественность языка стоит проверить с носителем.

Перед отправкой каждой картинки создаётся краткая подпись на выбранном языке.
При включении «Учитывать содержимое скриншота» изображение также передаётся
в OpenAI. Иначе API получает только основу текста и недавние подписи. Промпт
требует сохранять смысл и не выдумывать факты; результат генерации стоит проверить
на примерах. Точные повторы подписи (без учёта регистра и пробелов) отвергаются:
после трёх неудачных попыток задача останавливается. Семантическую уникальность
и точность модель не гарантирует. Используйте исходный текст без изменений,
когда нужна точная фиксированная подпись.

Полученная подпись сохраняется у скриншота и доступна в редакторе. При ошибке
API задача останавливается; скриншот остаётся ожидающим, его можно отправить после
устранения ошибки и повторного включения. Успешная отправка использует картинку
один раз, как и обычный пул. Генерация и кнопка примера используют оплачиваемый
OpenAI API; реальный ключ и баланс требуются отдельно.

Интеграция использует [Responses API с изображениями](https://developers.openai.com/cookbook/examples/multimodal/document_and_multimodal_understanding_tips).

Если доставка не подтверждена или процесс оборвался во время отправки, задача
останавливается без автоматического повтора. Проверьте чат перед продолжением:
Telegram мог получить сообщение. Картинка с неподтверждённым статусом повторно
не выбирается. Для новой разовой отправки создайте новую задачу. Запускайте
только один экземпляр приложения с одной базой.

## Импорт tdata

1. Закройте Telegram Desktop и сделайте копию папки `tdata` своего аккаунта.
2. Создайте ZIP-архив этой папки. В архиве должен остаться файл `key_data`
   (обычно `key_datas`) и файлы сессий. Кэш медиа можно исключить из копии.
3. В разделе «Аккаунты» откройте «Импорт из tdata» и выберите архив.
4. Если папка защищена локальным кодом-паролем Telegram Desktop, укажите его.
   Это локальный пароль приложения, а не облачный пароль двухэтапной проверки.
5. Нажмите «Импортировать». Импортируются все доступные аккаунты папки;
   уже добавленные номера пропускаются.

Импорт использует существующие сессии и профиль Telegram Desktop через
[opentele2](https://opentele2.github.io/). Нужен доступ сервера к Telegram.
Поддерживается один каталог tdata на архив. Ограничения: 64 МБ на запрос,
128 МБ распакованных данных, 5000 записей в архиве. Временная копия удаляется
после обработки; в базе остаются сессии аккаунтов.

Папка tdata и база содержат ключи доступа к аккаунтам. Не публикуйте их.
В исходном проекте нет входа в саму веб-панель: используйте её локально
или закройте доступ к ней средствами вашего сервера.

## Массовое редактирование профилей

В «Аккаунтах» отметьте нужные строки или выберите все и нажмите
«Редактировать выбранные». За один предпросмотр доступны до 50 аккаунтов.
Имя и фамилия создаются по отдельному промпту для страны, языка или сообщества.
Названия в панели меняются только с включённой соответствующей галочкой.
Для «О себе» доступны сохранение без изменений, очистка, одинаковый текст
и разные описания по промпту. Необязательная полная HTTP(S)-ссылка добавляется
к тексту без переформулирования. Длина описания со ссылкой проверяется отдельно
для каждого аккаунта (обычно 70, для Premium 140 символов UTF-16).

Предпросмотр читает текущие профили из Telegram, но не изменяет их. После
подтверждения аккаунты сохраняются последовательно; результат виден в каждой
строке. Отключённые аккаунты пропускаются. Изменившееся после предпросмотра поле
не перезаписывается. При неподтверждённом результате сохранение останавливается
без автоматического повтора: сначала проверьте профиль в Telegram.

Предпросмотр действует 15 минут, хранится только в памяти одного экземпляра
приложения и исчезает при перезапуске. Генерация использует существующие
`OPENAI_API_KEY` и `OPENAI_MODEL`. В OpenAI передаются только заданные вами
промпты, число вариантов и ограничения; текущие профили, номера и сессии
автоматически не отправляются. Для очистки и одинакового текста API не нужен.
Перед применением проверьте сгенерированные имена и описания.

Привязанный к профилю канал отображается в профиле аккаунта. Кнопка «Убрать
канал из профиля» отвязывает его после подтверждения, не удаляя сам канал,
сообщения или членство аккаунта. Для выбранных аккаунтов такое же действие
доступно в блоке «Канал в профиле» массового редактирования, через предпросмотр
и подтверждение. По умолчанию канал остаётся без изменений; OpenAI для отвязки
не нужен. Если привязка изменилась после загрузки профиля или предпросмотра,
изменение блокируется. При частичном сохранении нужно проверить профиль
и создать новый предпросмотр, а не повторять старое действие.

## AI-модератор и информационный ассистент

Вкладка «AI-ассистент» назначает один существующий аккаунт конкретному чату.
Это отдельный модуль: задачи по расписанию, пулы скриншотов и профили не меняются.
Нужны существующие `OPENAI_API_KEY` и `OPENAI_MODEL`, доступ аккаунта к чату,
а для удаления сообщений также права администратора Telegram. Таблицы модуля
создаются автоматически при следующем запуске приложения. Новые конфигурации
выключены; аккаунт не вступает в чат автоматически.

Режимы:
- `OFF`: нет анализа и действий ассистента.
- `OBSERVE`: анализ и журнал без отправки и удаления.
- `ASSIST`: предложения в разделе «Проверка», действия только после подтверждения.
- `AUTO`: разрешённые ответы и удаления после проверок. Требует отдельного согласия.

Обозначьте выбранный аккаунт как AI-ассистента в самом чате; модуль не меняет
его Telegram-профиль автоматически. Начните с `OBSERVE`, затем проверьте `ASSIST`
на своих примерах. Пороги уверенности
модели не являются гарантией точности. Качество амхарского, латинского амхарского,
оромо и Vision нужно проверить на реальных примерах с носителями языка.
Модуль учитывает сообщение, ответ на другой пост, до 20 недавних сообщений и до
5 сообщений пользователя. Приветствие отправляется одному пользователю один раз.
Изображения анализируются только с включённым разрешением Vision; ошибки и
сомнения не приводят к автоудалению. Безопасный игровой или платёжный скриншот
не удаляется лишь из-за его категории. Жалобы и неоднозначные случаи остаются
на проверке; для платежей и аккаунта используется фиксированное направление
в официальную поддержку, без обещаний и проверки статуса транзакции.

Если на квитанции, SMS или USSD-подтверждении видны персональные платёжные данные,
подготавливается предупреждение не публиковать такие скриншоты. При включённом
направлении в поддержку оно также содержит `support@betjam.com` для проблем
с депозитом. Предупреждение можно отправить без удаления: отключённое разрешение
на удаление не мешает безопасному ответу. Ошибка Vision не заменяется догадкой.
Для изображений без содержательной подписи язык берётся из настройки
«Язык ответов без подписи» (по умолчанию амхарский), а не из банковского интерфейса.
Поле добавляется автоматически и для уже созданных ассистентов.

При сбое журнал показывает этап (получение изображения, OpenAI или проверка
действия), тип ошибки и безопасную подсказку. Сырые ответы API, ключи, номера
и содержимое перевода в диагностике не выводятся. Предыдущие неудачные решения
автоматически не повторяются. При `REVIEW` сначала проверьте режим и причину;
в `ASSIST` даже корректное предупреждение отправляется только после подтверждения.

На странице ассистента блок «Диагностика» проверяет наличие и формат файлов
анализа, настройки, согласие, подключение и показывает последний сбой и успешный
анализ. Кнопка «Проверить Telegram» проверяет членство в чате, право удаления и
чтение официального канала без отправки сообщений, вступления или удаления.
Результаты прав актуальны пять минут и сбрасываются при изменении настроек.
Наличие API-ключа не подтверждает баланс, доступ к модели или работоспособность
OpenAI: ошибки реального анализа отображаются отдельно. При Docker-развёртывании
словарь `data/ethiopia_slang.json` включён в сборку; остальные файлы `data/`
по-прежнему исключены.

В «Категориях автоудаления» отдельно выбираются персональные данные, платёжные
реквизиты и документы. Мошенничество управляется разрешением его выявления.
Категории не включают удаление сами по себе: нужны `allow_delete`, режим `AUTO`,
порог уверенности, Vision для изображений и право Telegram. Для отключённых
чувствительных категорий вместо удаления может быть подготовлено предупреждение.
Ручное удаление модератором остаётся отдельным подтверждаемым действием.

После выключения назначение можно удалить с подтверждением. Это безвозвратно
удаляет его журнал, память пользователей и источники, освобождая чат для нового
назначения. Аккаунт Telegram и сообщения в чате не удаляются; выполняющийся
анализ или действие блокирует удаление. Новые поля автоматически добавляются
в существующую базу при запуске без включения ранее отключённого удаления.

Информационные ответы возникают только по запросу пользователя и используют
подтверждённые свежие записи: статус, связь опубликованного кода с постом,
объяснение терминов или содержания публикации. Приложение добавляет ссылки
на источники. Нет проактивной рекламы, рекомендаций играть, вносить депозит
или инструкций по регистрации, получению и отыгрышу игровых бонусов.

В «Источниках» можно вручную прочитать последние 3 текстовых поста назначенного
официального канала, импортировать статическую страницу `https://betjam.com/aa/`
или добавить справочную запись вручную. Новые и отредактированные текстовые посты
канала обрабатываются при получении Telegram-событий активным ассистентом.
Все импортированные записи требуют проверки человеком. Факты действуют
72 часа после подтверждения по умолчанию (настраивается от 1 до 168 часов).
Редактирование или удаление исходного поста снимает подтверждение. Пост об
окончании можно явно связать с исходной записью; сохраняется история версий.
Пропущенные во время отключения события автоматически не восстанавливаются:
перед включением записи нужно перепроверить.

Импорт сайта читает только доступный HTML без JavaScript и перенаправлений.
Работа на реальном сайте BetJam не подтверждена: если он требует JS или блокирует
чтение, используйте проверенную вручную запись. Посты канала без текстовой подписи
не распознаются как справочные источники по изображению. Автоматическое
сопоставление нескольких акций и всех постов истории не реализовано.

Текст и выбранные изображения передаются в оплачиваемый OpenAI API только после
явного разрешения. Распознаваемые контакты и числовые идентификаторы маскируются,
но это не полная анонимизация: изображения могут содержать персональные данные.
Они обрабатываются в памяти без сохранения файлов. В API установлен `store=False`,
что не заменяет проверку политики обработки данных OpenAI. Локальный контекст
старше 7 дней и решения старше 30 дней очищаются при следующем входящем сообщении;
минимальная память пользователя для пауз и приветствий хранится отдельно.

Есть паузы по чату, пользователю и теме, лимит 12 анализов в минуту на конфигурацию
и срок действия решения 15 минут. Перед действием повторно проверяются сообщение,
настройки, источники и права. Неизвестный результат доставки не повторяется
автоматически; после прерывания процесса его нужно сверить с Telegram.
«Выключить» останавливает новые действия, но не отменяет уже переданный запрос.

У назначенного активного ассистента старые правила ключевых слов в этом же чате
не запускаются для его аккаунта, чтобы избежать двойных ответов. Для остальных
аккаунтов и чатов правила остаются прежними; `OFF` возвращает прежнее поведение.
Запускайте один экземпляр приложения и ограничьте доступ к веб-панели:
встроенной авторизации администратора в исходном проекте нет.

## Очередь Анализа И Восстановление

Полученные события активного ассистента сохраняются в базе до обращения к AI.
Если чат занят анализом или достигнут лимит 12 анализов в минуту, сообщение
остаётся в `QUEUED`, а не теряется из-за лимита. Вкладка «Очередь анализа» и
диагностика показывают ожидание, число попыток и время следующей проверки.
Планировщик проверяет очередь каждые 5 секунд, до четырёх чатов за проход;
сообщения каждого чата обрабатываются последовательно.

После временного сбоя чтения Telegram или анализа OpenAI предусмотрено не более
трёх попыток на сообщение. Используется увеличивающаяся задержка с небольшим
случайным смещением; `Retry-After` и `FloodWait` соблюдаются. Ошибки ключа,
квоты/баланса, модели, изображения и формата результата автоматически не
повторяются. Они направляются на проверку, а не в обучение. Для OpenAI штатные
повторы SDK остаются отключены, поэтому попытки не умножаются вложенными циклами.

При перезапуске повторяется только незавершённый анализ. Перед повтором сообщение
и контекст ответа заново читаются из Telegram; изображения обрабатываются в
памяти и не сохраняются в очередь. Изменённые, удалённые сообщения, отключённые
назначения и изменившиеся настройки отменяют обработку. Задания старше 10 минут
не выполняются автоматически: это предотвращает поздние ответы и наказания.
Для хранения очереди после деплоя нужна сохраняемая база данных; временный диск
Render или `sqlite:///:memory:` не обеспечивает сохранность при замене сервиса.

Очередь не повторяет отправки, удаления и баны. Прерванное действие остаётся
`UNCERTAIN` и требует сверки с Telegram. Она также не восстанавливает сообщения,
события которых приложение не успело получить, и не обновляет официальные
источники автоматически. Запускайте один экземпляр Telegram-менеджера на базу.

## Языки, Исправления И Тестовые Прогоны

У каждого ассистента свои язык, языковой профиль, стиль, словарь и официальный
контакт поддержки. Профиль «Эфиопия» подключает существующий небольшой словарь;
«Общий» его не использует. Новые назначения по умолчанию используют общий
профиль и английский, без контакта BetJam. Существующие назначения сохраняют
прежние настройки после автоматической миграции базы.

Можно выбрать русский и другие языки из списка или «Другой язык» с названием
языка/диалекта. Словарь задаётся строками `выражение = значение` (до 30 строк).
Стиль и примеры не отменяют обязательные правила безопасности. Язык интерфейса
на скриншоте не определяет язык ответа. Текст на кириллице, арабском и других
письменностях теперь также считается языковой подсказкой.

Готовые шаблоны предупреждения и поддержки есть для английского, русского,
амхарского, амхарского латиницей и оромо. Для остальных языков перед включением
задайте проверенные человеком тексты на основном языке этого чата. Эти тексты
применяются только к выбранному основному языку; для иных языков без шаблона
предупреждение/обращение в поддержку требует модератора. Проверьте переводы с
носителем. Контакт поддержки добавляется приложением, а не придумывается AI.
Источник канала назначается отдельно для каждого чата. Импорт сайтов пока
ограничен прежним BetJam HTML-источником, произвольные сайты и JS не добавлены.

Вкладка «Тесты и исправления» хранит до 50 вручную добавленных обезличенных
примеров на ассистента: текст, reply-контекст, необязательное изображение и
ожидаемые метки. В журнале «Добавить исправление» открывает эту же форму с
исходным решением. Исправление не отправляет ответ и не меняет сообщение в
Telegram. После подтверждения модератором до 5 примеров этого чата
передаются как ограниченный контекст будущих анализов. Это не дообучение модели.
Снятие подтверждения/удаление прекращает использование примера; готовые старые
решения становятся неактуальными. Для замены примера удалите его и добавьте новый.

Каждый прогон требует отдельного согласия на платный OpenAI-запрос. Работает и
в OFF без подключённого Telegram, но требует API-ключ и разрешение обработки
данных; для изображения дополнительно нужен Vision. Путь прогона не получает
Telegram-клиент и не создаёт исполнимого решения в живом журнале. Он применяет
те же анализ и защитную политику, исключая проверяемый пример из контекста
исправлений. Права Telegram, паузы, историю пользователя и доставку не проверяет.
PASS означает только совпадение заданных меток, не гарантию качества ответа.

История содержит PASS/FAIL/ERROR/STALE, конкретные расхождения, модель, версии
настроек/источников и отпечаток промта. Повтор одного отправленного запроса
не вызывает AI второй раз. Прерванные тесты не повторяются автоматически;
лимит — 12 прогонов в минуту на ассистента. Изменение настроек или источников
во время прогона помечает его неактуальным.

Автоматического чтения истории Telegram для тестов нет. Маскирование текста не
заменяет ручное обезличивание. Тестовые изображения сохраняются в базе только
после подтверждения, без публичной ссылки и без EXIF; удаление примера удаляет
изображение и прогоны. Удаление назначения также очищает примеры. История тестов
не очищается по таймеру, удаляйте ненужные примеры вручную. Ограничьте доступ к
панели и резервным копиям базы: встроенной авторизации администратора пока нет.
Вторичная Vision-проверка, fast-path, бюджет токенов и редактор версий системных
правил относятся к следующему этапу и этим изменением не добавлены.

## Тренировка И Правила Модерации

Во вкладке «Тренировка» автоматически появляется вопрос по сообщению, которое
успешно проанализировано, но требует ручного решения. Показаны текст с маскированием
распознаваемых контактов/идентификаторов, причина неуверенности и ссылка на исходное сообщение. Платёжные/личные
данные скрываются; входящие изображения туда не сохраняются. Сбои API не являются
языковыми примерами и остаются в диагностике. Обычные подтверждения режима ASSIST
не добавляются в очередь, если AI уже подготовил допустимый ответ.

Администратор выбирает язык, ситуацию, категорию и действие, даёт пояснение и
при необходимости правильный ответ. «Сохранить пояснение» создаёт подтверждённый
пример этого чата, закрывает вопрос и не выполняет действий в Telegram. Один
вопрос нельзя сохранить повторно. Изменённые/удалённые сообщения снимаются с
очереди; вопрос можно пропустить без обучения. Управление сохранёнными пояснениями
и снятие подтверждения доступны через «Тесты и исправления». В анализ передаются
до 5 подтверждённых примеров: совпадения слов имеют приоритет, иначе выбираются
последние. По умолчанию это поиск по словам; он не меняет веса модели.

Опция «Смысловая память» отдельно разрешает дополнительные платные текстовые
запросы OpenAI `text-embedding-3-small` (256 измерений). Она выключена по умолчанию,
включая старые базы. Требуются API-ключ и согласие передачи данных. До 50
подтверждённых примеров индексируются лениво, только для своего чата; на анализ
выбираются до 5 близких по смыслу пояснений. Текст ограничен 800 символами и
маскируется; изображения embeddings не получают. Кеш в базе повторно используется
при следующем сообщении и повторе анализа; изменение текста меняет отпечаток.
Первый запрос дороже следующих: он индексирует ещё не закешированные примеры.
Тестовые прогоны используют тот же поиск, но исключают проверяемый пример.
Это поиск контекста, а не дообучение, уверенность модели или разрешение на наказание.

Сбой embeddings не блокирует основной анализ: включается поиск по словам и пауза
10 минут для дополнительных запросов. В диагностике видны состояние памяти,
число индексированных примеров и причина сбоя; в журнале — метод и ID выбранных
пояснений. Сохранение настроек сбрасывает паузу. Чтение админки не вызывает API.
Исходящие API-расходы можно ограничить в проекте OpenAI; глобальный бюджет
приложения пока не добавлен. Качество поиска на амхарском и других языках нужно
проверить на примерах с носителем языка перед AUTO.

Повторяющиеся вопросы в тренировке собраны в группы. Точные повторы работают
без embeddings; смысловые группы используют только уже закешированные текстовые
вопросы и косинусное сходство не ниже 0.95. Язык, тема, категория и действие
должны совпадать; изображения, reply-сообщения, скрытые личные данные и длинные
тексты не объединяются по смыслу. Старые вопросы автоматически не переиндексируются.
Сходство не гарантирует одинаковый смысл: админ проверяет каждый вопрос и
выбирает флажками, к каким применить одно пояснение. Без выбора закрывается только
основной вопрос. Сохранение создаёт один пример и не выполняет действий в Telegram;
изменение/обработка участника группы отменяет сохранение целиком. Неотмеченные
вопросы остаются открытыми. Подписанный выбор группы действует 15 минут.

Во вкладке «Модерация» можно добавить до 20 правил: обезличенный пример нарушения,
пояснение, исключения и действие DELETE, BAN или DELETE_BAN. Правила можно редактировать,
отключать и удалять. Они относятся только к своему чату. Включение правила не
включает разрешение удаления/бана. Изменение правил отменяет старые готовые
решения и помечает текущие тесты неактуальными. Для DELETE по правилу AI должен
вернуть классификацию RULE_VIOLATION и ID включённого правила DELETE; простое
совпадение слов не запускает наказание. Эти правила также проверяются в replay.

BAN отдельно разрешается в настройках ассистента и по умолчанию выключен, в том
числе после миграции старой базы. Нужны включённое правило BAN, классификация
нарушения, уверенность не ниже порога (0.98 по умолчанию; диапазон 0.95–1),
супергруппа и право аккаунта блокировать участников. Изображения требуют Vision
и достаточной уверенности. Перед баном сверяются исходное сообщение, его автор,
настройки и роль участника. Каналы, анонимные отправители, собственные аккаунты,
администраторы и владельцы не банятся; неподтверждённый автор/роль блокирует действие.
Личные платёжные данные сами по себе не являются основанием для бана.

В OBSERVE бан не выполняется; в ASSIST нужно отдельное подтверждение действия
модератором, в AUTO возможен автоматический бан в пределах разрешений. BAN
бессрочно запрещает участнику доступ к сообщениям; сообщение отдельно не
удаляется. Для разблокировки используйте админку Telegram. Результат BANNED
попадает в журнал, неизвестный результат приложение автоматически не повторяет.

DELETE_BAN («Удалить сообщение и заблокировать автора») требует включённого
правила с этим же действием, обоих разрешений в настройках и обоих прав Telegram.
Правило только удаления или только бана не повышается до комбинированного действия.
Сначала выполняется бан, затем повторно проверяются исходное сообщение и настройки
перед удалением. Telegram не поддерживает атомарный бан с удалением: журнал отдельно
показывает результат каждого шага. DELETED_BANNED означает подтверждение обоих шагов,
PARTIAL — подтверждённый бан с незавершённым удалением. При неопределённом результате
или перезапуске действия не повторяются: проверьте состояние в Telegram вручную.

В «Тренировке» удаление за нарушение сообщества, бан и DELETE_BAN сохраняются
как правила вкладки «Модерация», а не как безопасные примеры ответов. Выберите
категорию «Нарушение правила сообщества» и ситуацию «Спам» или нарушение правила,
подтвердите сохранение правила. Включение правила задаётся отдельным флажком;
разрешения на удаление и бан автоматически не включаются. Сохранение не выполняет
действий в Telegram, в том числе для отмеченных вопросов группы.

Ответы и предупреждения отправляются с reply_to исходного входящего сообщения,
а не отдельным сообщением и не ответом на процитированный официальный пост.
Предупреждение о личных/платёжных данных отправляется до удаления, чтобы Telegram
мог принять ссылку на исходное сообщение. После удаления клиент Telegram может
показывать удалённое сообщение вместо его содержимого. Если отправка предупреждения
не подтверждена, отдельного повторного ответа без привязки нет.

Уверенность модели не является гарантией: перед AUTO проверьте правила на
обезличенных примерах, включая цитаты, вопросы и жалобы на мошенников. Ни
примеры, ни пояснения не отменяют обязательные правила безопасности и свежие
официальные источники. Возможности одинаковы для языковых профилей всех чатов.

## Проверки

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

Тесты проверяют формы, вложения, AI-подписи, очередь скриншотов, отложенные ответы, повторные отправки,
дубликаты, миграцию существующей базы, русские страницы и обработку архивов.
Тесты AI-ассистента дополнительно проверяют режимы, согласия, права удаления,
устаревшие решения, подтверждение и историю источников, контекст, маскирование
и отсутствие повторов при неизвестном результате. Сетевые вызовы Telegram
и OpenAI в тестах заменены имитациями. Реальный вход из tdata
и доставка сообщения требуют вашего аккаунта и не проверяются этими тестами.
